# دليل اختبار النظام والتطبيق للمختبرين

> الإصدار: 2026-10-31
> النطاق: نظام إدارة المنشأة، لوحة إدارة طفولة تيك، تطبيق المعلم، تطبيق ولي الأمر، الإشعارات، المساعد الذكي، والأمان.
> هذه قائمة قبول يدوي. وضع علامة النجاح يعني أن المختبر نفّذ الخطوات على البيئة المحددة وشاهد النتيجة المتوقعة، وليس مجرد أن الزر ظهر.

## طريقة تسجيل النتيجة

استخدمي لكل حالة إحدى القيم: `ناجح`، `فاشل`، `محجوب`، `غير منطبق`.

| الحقل | ما يُكتب |
|---|---|
| رقم الحالة | مثل `WEB-STU-01` |
| البيئة | محلي / تجريبي / إنتاج |
| الجهاز والمتصفح | مثال: Android 14 أو Chrome 130 |
| الحساب والدور | مديرة / معلمة / ولي أمر / مشرف طفولة تيك |
| النتيجة | ناجح / فاشل / محجوب / غير منطبق |
| الفعلي | وصف مختصر لما حدث |
| الدليل | لقطة شاشة أو فيديو أو رقم سجل |
| الشدة | حرجة / عالية / متوسطة / منخفضة |

## بيانات الاختبار المطلوبة قبل البدء

- [ ] `PRE-01` منشأتان منفصلتان: منشأة A ومنشأة B، لاختبار عزل البيانات.
- [ ] `PRE-02` حساب مديرة كامل الصلاحيات في كل منشأة.
- [ ] `PRE-03` حساب موظفة بصلاحيات محدودة، وحساب معلمة مرتبط فعليًا بملف معلمة.
- [ ] `PRE-04` حساب موظفة غير مرتبط بملف معلمة لاختبار رسائل الربط.
- [ ] `PRE-05` ولي أمر مرتبط بطفل واحد، وولي أمر مرتبط بطفلين، وولي أمر من منشأة أخرى.
- [ ] `PRE-06` فصلان صباحيان وفصل مسائي، أحدها ممتلئ والآخر متاح.
- [ ] `PRE-07` أطفال نشطون، طفل ملغي الاشتراك، طفل مؤرشف، وطفل بلا فصل.
- [ ] `PRE-08` معلمات نشطات، معلمة مؤرشفة، ومعلمة بلا حساب تطبيق.
- [ ] `PRE-09` حدث عام، حدث لفصل، حدث لمعلمة، وحدث لمعلمة أخرى.
- [ ] `PRE-10` فواتير مدفوعة ومتأخرة، مصروف مرة واحدة، ومصروف شهري.
- [ ] `PRE-11` منشأة تتطلب مراجعة تقارير الرعاية وأخرى ترسل مباشرة.
- [ ] `PRE-12` هاتف Android فعلي مثبت عليه أحدث APK، مع إمكانية اختبار التطبيق في الخلفية.
- [ ] `PRE-13` تفعيل الإشعارات في الهاتف وإضافة جهاز ثانٍ إن أمكن لاختبار تعدد الأجهزة.
- [ ] `PRE-14` تحديد موقع المنشأة ونطاق الدخول والخروج، وربط حساب المعلمة بملفها.

# أولًا: نظام إدارة المنشأة على الويب

## 1. الدخول والجلسات والحساب

- [ ] `WEB-AUTH-01` الدخول ببريد وكلمة مرور صحيحين؛ المتوقع فتح لوحة المنشأة الصحيحة فقط.
- [ ] `WEB-AUTH-02` إدخال كلمة مرور خاطئة؛ المتوقع رسالة عامة لا تكشف هل البريد مسجل.
- [ ] `WEB-AUTH-03` فتح رابط داخلي بلا جلسة؛ المتوقع التحويل لتسجيل الدخول ثم العودة للرابط بعد نجاح الدخول.
- [ ] `WEB-AUTH-04` تجربة حساب معطل؛ المتوقع رفض الدخول وعدم إنشاء جلسة.
- [ ] `WEB-AUTH-05` تسجيل الخروج ثم استخدام زر الرجوع؛ المتوقع عدم ظهور بيانات اللوحة المحمية.
- [ ] `WEB-AUTH-06` طلب استعادة كلمة المرور، استلام الرمز، تعيين كلمة جديدة، ثم الدخول بها.
- [ ] `WEB-AUTH-07` إعادة استخدام رمز استعادة مستعمل أو منتهي؛ المتوقع الرفض.
- [ ] `WEB-AUTH-08` تفعيل التحقق بخطوتين، الخروج، ثم الدخول بالرمز الصحيح والخاطئ والمنتهي.
- [ ] `WEB-AUTH-09` ترك الجلسة حتى انتهاء صلاحيتها؛ المتوقع طلب تسجيل الدخول بدل عرض أخطاء داخلية.
- [ ] `WEB-AUTH-10` فتح الحساب نفسه في جهازين وتغيير الصلاحية أو تعطيله؛ المتوقع تطبيق التغيير على الطلب التالي.

## 2. الرئيسية

- [ ] `WEB-HOME-01` التحقق من ملخص حضور الأطفال والمعلمات لليوم ومطابقته لسجل الحضور.
- [ ] `WEB-HOME-02` وجود تقرير رعاية مرجع؛ المتوقع ظهور تنبيه مختصر يفتح صفحة التقارير المرجعة.
- [ ] `WEB-HOME-03` التحقق أن قسم الأحداث يعرض أحداث اليوم الحالي فقط.
- [ ] `WEB-HOME-04` عدم وجود بيانات؛ المتوقع حالات فارغة واضحة بلا أرقام مضللة أو أخطاء.
- [ ] `WEB-HOME-05` تحديث حضور أو حدث في تبويب آخر ثم العودة؛ المتوقع ظهور البيانات الجديدة دون بيانات مخزنة قديمة.

## 3. الأطفال وأولياء الأمور

- [ ] `WEB-STU-01` إنشاء طفل بأقل الحقول المطلوبة؛ المتوقع نجاح الحفظ وظهوره في القائمة.
- [ ] `WEB-STU-02` إرسال نموذج ناقص أو تاريخ غير صحيح؛ المتوقع تحديد الحقول الخاطئة دون إنشاء سجل جزئي.
- [ ] `WEB-STU-03` تعديل الاسم والجنس وتاريخ الميلاد والفترة والبيانات الصحية المسموحة؛ المتوقع حفظها وعرضها بعد التحديث.
- [ ] `WEB-STU-04` رفع صورة صالحة ثم استبدالها وحذفها؛ المتوقع ظهور الجديدة وعدم بقاء رابط الصورة السابقة.
- [ ] `WEB-STU-05` رفع ملف تقييم صالح وفتحه من حساب مصرح؛ المتوقع تنزيله أو عرضه من رابط محمي.
- [ ] `WEB-STU-06` رفع ملف أكبر من الحد أو بامتداد مزيف؛ المتوقع الرفض برسالة واضحة.
- [ ] `WEB-STU-07` تعيين الطفل لفصل ثم نقله؛ المتوقع تحديث الفصل والقوائم والسعة.
- [ ] `WEB-STU-08` محاولة إضافة طفل إلى فصل ممتلئ أو غير متوافق مع الفترة؛ المتوقع الرفض.
- [ ] `WEB-STU-09` إلغاء الاشتراك مع سبب وتاريخ؛ المتوقع تغيير الحالة وتثبيت تاريخ الخروج وبداية الاحتفاظ.
- [ ] `WEB-STU-10` تجديد الاشتراك؛ المتوقع تحديث تواريخ الاشتراك والرسوم دون تكرار غير مقصود.
- [ ] `WEB-STU-11` إعادة تفعيل طفل ملغي؛ المتوقع مسح بيانات الخروج وإعادته للحالة النشطة.
- [ ] `WEB-STU-12` أرشفة طفل ثم استعادته من السلة؛ المتوقع الحفاظ على ملفه وعلاقاته المسموحة.
- [ ] `WEB-STU-13` البحث بالاسم والفلترة حسب الفصل والحالة والجنس والفترة؛ المتوقع نتائج صحيحة مع إعادة ضبط الصفحات.
- [ ] `WEB-STU-14` تحديد عدة أطفال وتنفيذ إجراء جماعي؛ المتوقع تطبيقه على المحددين فقط.
- [ ] `WEB-STU-15` إضافة ولي أمر جديد برقم أو بريد صالح وربطه بالطفل.
- [ ] `WEB-STU-16` ربط ولي أمر موجود بطفل ثانٍ وتحديد الأساسي؛ المتوقع ظهور الطفلين في حسابه.
- [ ] `WEB-STU-17` إزالة علاقة ولي أمر غير أساسي؛ المتوقع عدم حذف حسابه أو علاقاته الأخرى.
- [ ] `WEB-STU-18` محاولة ربط ولي أمر أو طفل من منشأة B؛ المتوقع الرفض وعدم تسريب الاسم أو البيانات.
- [ ] `WEB-STU-19` إصدار فاتورة وتذكير دفع من ملف الطفل؛ المتوقع ربط العملية بالطفل الصحيح.
- [ ] `WEB-STU-20` التحقق أن مستخدمًا بلا صلاحية الصحة لا يرى الحقول الصحية حتى عبر الرابط أو API.

## 4. المعلمون والموظفون وحسابات التطبيق

- [ ] `WEB-STF-01` إضافة معلمة مع الفترة والمؤهل والراتب؛ المتوقع ظهورها في القائمة.
- [ ] `WEB-STF-02` تعديل بيانات معلمة؛ المتوقع تحديث الملف دون تغيير حساب التطبيق المرتبط خطأً.
- [ ] `WEB-STF-03` تعيين المعلمة لفصل وإزالتها منه؛ المتوقع انعكاس التغيير في الفصل والتقويم والتطبيق.
- [ ] `WEB-STF-04` إنشاء مناوبة بتاريخ ووقت وفصل، ثم تعديلها وحذفها.
- [ ] `WEB-STF-05` أرشفة معلمة مع سبب وتاريخ، ثم إعادة تفعيلها.
- [ ] `WEB-STF-06` إنشاء حساب تطبيق واختيار ملف المعلمة الصحيح وإرسال الدعوة.
- [ ] `WEB-STF-07` إنشاء حساب إداري بلا ربط معلمة؛ المتوقع ظهوره إداريًا وعدم ظهور ميزة الحضور بالموقع في التطبيق.
- [ ] `WEB-STF-08` إعادة إرسال دعوة غير مفعلة؛ المتوقع إبطال أو تجاوز الرابط القديم حسب السياسة ووصول الجديدة.
- [ ] `WEB-STF-09` تعطيل الحساب أثناء جلسة نشطة ثم إعادة تفعيله.
- [ ] `WEB-STF-10` تغيير دور الحساب؛ المتوقع تغير القوائم والصلاحيات فور إعادة الطلب.
- [ ] `WEB-STF-11` منع ربط ملف المعلمة نفسه بحسابين إن كان ذلك غير مسموح.
- [ ] `WEB-STF-12` إصدار فاتورة راتب وفتح PDF والتحقق من العربية والمبلغ والاسم.
- [ ] `WEB-STF-13` استيراد قائمة معلمات صحيحة ثم تجربة ملف ناقص أو مكرر.
