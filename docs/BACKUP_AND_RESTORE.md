> المهمة `1.16`. متطلب **إلزامي** قبل البيع حسب ملف متطلبات النظام (PDF).
> ⚠️ **الجزء التشغيلي يحتاج تفعيلاً منكِ** — الكود لا يستطيع تفعيل نسخ Neon نيابةً عنكِ.

---

## 1. الوضع الحالي

قاعدة البيانات على **Neon**. لدى Neon نوعان من الحماية، وهما ليسا نفس الشيء:

| | ما هو | يحمي من |
|---|---|---|
| **History retention** (مفعّل افتراضياً) | استرجاع لحظي لأي نقطة زمنية داخل نافذة الاحتفاظ | حذف بالخطأ · ترحيل خاطئ · تلف بيانات |
| **نسخة خارجية** (`pg_dump`) | ملف مستقل خارج Neon | فقدان الحساب · حذف المشروع · خطأ لدى المزوّد |

> 🔴 **الأولى وحدها لا تكفي.** إن ضاع حساب Neon أو حُذف المشروع، ضاع معه كل تاريخه.
> النظام يتعامل مع بيانات أطفال، والاعتماد على نسخة واحدة داخل المزوّد ليس خطة استعادة.

---

## 2. ما يجب تفعيله (خطوات يدوية)

### أ. رفع مدة الاحتفاظ في Neon
1. Neon Console ← المشروع ← **Settings → Storage**
2. اضبطي **History retention** على **7 أيام على الأقل** (الافتراضي أقصر في الخطة المجانية)
3. الخطة المدفوعة تسمح بـ30 يوماً — الأنسب لبيانات الأطفال

### ب. نسخة خارجية أسبوعية
شغّلي هذا الأمر أسبوعياً على جهازك أو على أي خادم، واحفظي الناتج **خارج Neon**:

```bash
pg_dump "$DATABASE_URL" --format=custom --no-owner --file="daycare-$(date +%Y-%m-%d).dump"
```

**أين تُحفظ**: مساحة سحابية مشفّرة، أو قرص خارجي. ⚠️ الملف يحتوي بيانات أطفال كاملة —
يُعامَل معاملة السجل الطبي، لا معاملة ملف مشروع.

### ج. تدوير النسخ
احتفظي بـ: آخر 4 نسخ أسبوعية + آخر 12 نسخة شهرية. الأقدم يُحذف **حذفاً آمناً**.

## 3. الاستعادة — وهنا المهم

> **نسخة احتياطية لم تُختبر استعادتها ليست نسخة احتياطية.**
> أكثر أنواع الفشل شيوعاً ليس غياب النسخة، بل اكتشاف أنها لا تُستعاد وقت الحاجة إليها.

### استعادة لحظية (Point-in-time) — للأخطاء الحديثة
1. Neon Console ← **Branches** ← **Restore**
2. اختاري اللحظة قبل الخطأ مباشرة
3. Neon ينشئ **فرعاً جديداً** — لا يمسّ الفرع الحالي
4. تحقّقي من الفرع الجديد أولاً، ثم بدّلي `DATABASE_URL` في Vercel

**لماذا فرع لا استبدال**: الاستبدال المباشر يعني أن استعادة خاطئة تُتلف ما تبقّى.

### استعادة من ملف — للكوارث
```bash
pg_restore --dbname="$TARGET_DATABASE_URL" --no-owner --clean --if-exists daycare-2026-08-02.dump
```
⚠️ `--clean` يحذف الجداول قبل الاستعادة. **لا تُشغَّل على قاعدة الإنتاج** — أنشئي قاعدة
جديدة، استعيدي إليها، تحقّقي، ثم بدّلي الرابط.

- [ ] تسجيل دخول فعلي على الفرع المستعاد
- [ ] فتح ملف طفل والتأكد من ظهور الفواتير والحضور
- [ ] **توثيق كم استغرقت العملية** — هذا رقم الـRTO الحقيقي، لا التقديري

استعلام تحقّق سريع:
```sql
SELECT 'schools' AS t, COUNT(*) FROM "School"
UNION ALL SELECT 'students', COUNT(*) FROM "Student"
UNION ALL SELECT 'teachers', COUNT(*) FROM "Teacher"
UNION ALL SELECT 'invoices', COUNT(*) FROM "Invoice"
UNION ALL SELECT 'attendance', COUNT(*) FROM "Attendance";
```

## 5. ما لا تحميه النسخة الاحتياطية

| الخطر | لماذا لا تكفي النسخة | ما يحميه فعلاً |
|---|---|---|
| حذف موظف لبيانات بالخطأ | الاستعادة تعيد **كل شيء** لتلك اللحظة وتُلغي عمل بقية اليوم | سلة المحذوفات (30 يوماً) — موجودة ومطبَّقة |
| التجهيل بعد انتهاء مدة الاحتفاظ | مقصود ونهائي، والاستعادة منه **تُعيد بيانات شخصية وجب إتلافها** — مخالفة | لا شيء، وهذا هو المطلوب. راجعي [DATA_LIFECYCLE.md](DATA_LIFECYCLE.md) |
| ملفات base64 داخل الصفوف | مشمولة في النسخة، لكنها تُضخّمها كثيراً | نقل الملفات إلى R2 (`0.34/0.35`) |
| تسريب النسخة نفسها | النسخة **بيانات أطفال كاملة بلا أي تشفير على مستوى الحقول** | تخزين مشفّر + وصول محدود |

## 6. خطة الاستجابة للحوادث

مطلوبة في ملف المتطلبات (PDF، قسم "ماذا لو تم اختراق النظام؟"):

1. **الاكتشاف** — تنبيه من `ERROR_WEBHOOK_URL` أو بلاغ من حضانة
2. **الاحتواء** — تعليق الاشتراك المتأثر من لوحة الأدمن · تدوير `NEXTAUTH_SECRET`
   و`ADMIN_JWT_SECRET` (يُبطل كل الجلسات فوراً) · تدوير `attendanceToken`
3. **التقييم** — `ActivityLog` و`ExportAuditLog` يجيبان: مَن دخل، ومَن صدّر ماذا
4. **الاستعادة** — حسب القسم 3
5. **الإبلاغ** — التزامات PDPL عند انطباقها · إبلاغ الحضانات المتأثرة
